## 本轮发现并已修复

| 问题 | 影响 | 修复 |
|---|---|---|
| OTA 命令绕过发布权限 | 客户或只有 `node:write` 的管理员可以通过通用命令队列请求安装签名应用包，包括旧版本 | 客户接口拒绝 `ota-update`；管理员额外校验 `ota:write`，覆盖禁止入队及授权成功测试 |
| 客户状态更新写错字段 | 将订阅的 `suspension_reason` 写入 `customers`，修改客户状态返回数据库错误 | 将字段更新移到订阅接口，覆盖客户暂停/恢复测试 |
| 编辑订阅未记录人工暂停 | 原本因流量暂停的订阅经编辑接口人工暂停后，仍可能被月度重置自动恢复 | 编辑状态时同步暂停原因；覆盖续费及跨月后保持人工暂停、激活清除原因 |
| 私钥忽略范围被削弱 | 为提交 OTA 公钥移除了全局 `*.pem` 忽略，其他位置的 PEM 私钥可能被误暂存 | 恢复 `*.pem`，仅放行指定 OTA 公钥；`keys/` 保持忽略 |
| 文档与实现不符、OTA 测试未进 CI | 旧文档仍称应用 OTA 没有事务回滚、热点密码从 MAC 派生；CI 未运行新增设备测试 | 同步说明，并把 OTA/硬件隔离回归及依赖接入 CI |

## 尚未解决的已知问题与边界

以下条目仍需后续工作，不能视为本次提交已完成。

| 优先级 | 问题及触发条件 | 当前影响与后续工作 |
|---|---|---|
| P1，上线前阻断 | 完整 Armbian 镜像尚未构建，三组设备未真机验收 | Zero2 1 GB/2 GB、R28S 1 GB 的 U-Boot 编译和隔离测试不能证明完整系统可启动。需在足够磁盘空间的构建机实编译，再用 32/64 GB TF 卡验证冷启动、网络、内存负载、A/B 升降级与断电恢复。R28S 的厂商内核/AIC8800 集成尤其需要实机验证。 |
| P1，无人值守恢复限制 | 内核或引导阶段硬锁死，无法触发下一次重启 | 尚无经真机验证的 RK3528 硬件看门狗适配。A/B 尝试次数只在重启时递减，需外部看门狗或人工断电；U-Boot 损坏、TF 故障也无法用 A/B 修复。 |
| P1，存量升级要求 | 已上线设备仍使用共享凭证、旧代理或单系统分区 | 新后台拒绝旧凭证和旧 GET 授权接口；仅升级后台会中断旧设备服务，旧节点上的缓存代理配置也不会自动失效。需维护窗口和可信 SSH 安装独立 token/新版代理；A/B 首刷必须离线备份、整盘刷写后恢复身份。 |
| P2，套餐执行不完整 | 设置套餐速度或并发设备数限制 | 当前是配置字段，尚无严格的流量整形及并发终端限制；不能按已经强制执行来售卖这些保证。 |
| P2，计量与连接影响 | 到达额度、撤销 UUID、采样期间断电或失联 | 按约 15 秒周期计量，最长 45 秒授权加守护调度延迟，不是逐字节硬限额；突然断电可能丢失末次采样后的用量。撤销会重启整台节点的 Xray，其他用户也会短暂重连。 |
| P2，存储会增长 | 长期运行、多次代理重启或频繁上传发布包 | `node_traffic_counters` 保留历史运行周期，已发布 OTA 包不自动清理；需要容量监控与带安全水位的保留/回收策略，不能直接删计数位置以免历史重报重复计费。 |
| P2，OTA 管理记录与扩展能力 | 同一节点重新分配任务或多实例并发上传 | 每节点只有当前分配，重新分配会覆盖旧任务状态；尚无完整升级历史。分片互斥为进程内锁，上传需固定到同一 Registry 实例，不能无约束地跨副本分发。 |
| P2，初始安装及数据回滚范围 | 首次安装 OTA 客户端时断电，或 hook/新固件修改共享数据格式 | 首次安装器有普通失败恢复，断电仍需从保留备份人工恢复/重跑。应用事务只恢复声明文件与服务状态，不能撤销远程副作用/数据库迁移；固件共享数据必须兼容旧版本。 |
| P2，历史订单与迁移 | 对旧订单退款、人工修改到期日，或执行 SQL 迁移中断 | 无法可靠推断历史余额抵扣与开通关系，需核对补录；有歧义的退款返回 409。MySQL DDL 非完整事务，迁移中断可能留下部分结构，需要备份及人工核对后恢复。外部渠道资金退款仍需渠道或人工执行。 |
